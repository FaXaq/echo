# Design-sync notes — apps/web (Echo Design System)

## Repo shape

- The design system is `apps/web/src/components/ui/*.tsx` (shadcn/ui + Tailwind v4 + Radix). No standalone package/dist exists — it's consumed directly by the app, never built or published separately.
- Scope is intentionally limited to top-level files directly under `components/ui/` (41 files as of 2026-08-11, 25 storied — see below). `components/ui/event-calendar/` is a feature-specific calendar subtree (data-fetching, business logic) and is excluded — see titleMap below. This matches AGENTS.md's rule that `components/ui` must stay presentational.
- Synthetic entry: `.design-sync/entry.ts` does `export *` from every top-level component file (relative imports, e.g. `../apps/web/src/components/ui/button`). **This file is hand-maintained and not auto-derived** — a re-sync must diff it against `find apps/web/src/components/ui -maxdepth 1 \( -name "*.tsx" -o -name "*.ts" \) ! -name "*.stories.*" ! -name "*.test.*"` before building; a stale entry (referencing a deleted file) fails the whole bundle build with `Could not resolve`. After editing entry.ts, regenerate `.d.ts` too: `apps/web/node_modules/.bin/tsc -p .design-sync/tsconfig.entry.json` (stale/absent `.d.ts` for a new component just yields a stubbed prop signature, not a hard failure, but do it anyway).
- `data-table-features.ts` is a TanStack Table features config object, not a visual component — deliberately left OUT of entry.ts. `data-table.tsx` imports it via the `@/ui/*` path alias so it still bundles correctly as an internal dependency.
- Unstoried components currently in entry.ts but with **no card in the synced project** (no `.stories.tsx` exists to pair against, so the storybook-shape converter silently excludes them from `components:` — they're still in the JS bundle for type purposes, just no verified preview, no `.d.ts`/`.prompt.md`): `AspectRatio`, `Attachment`, `AttachmentList`, `ButtonGroup`, `Command`, `DataTable`, `DataTableColumnHeader`, `DataTablePagination`, `DataTableViewOptions`, `InputGroup`, `Item`, `Popover`, `ScrollArea`, `Textarea`, `Toast`, `Toggle`. Add `.stories.tsx` files for these to get them synced with real previews — the `data-table-*` blocks in particular ship as of 2026-08-11 "not wired to any feature yet" (per its commit message), so likely still worth a story pass once a real usage exists.

## [GENERAL] Config gotchas (all in `.design-sync/config.json` already — record here so a re-sync doesn't rediscover them)

- `storybookConfigDir` must be the **`.storybook/` directory itself** (`apps/web/.storybook`), not its parent. Passing the parent silently breaks `resolveStorySources` (story source pairing) → 0 previews generated, every component falls to the floor card, with no loud error.
- `cssEntry` must point **directly** at the compiled CSS asset inside `.design-sync/sb-reference/assets/iframe-<hash>.css` (Tailwind v4 can't be compiled by plain esbuild — `@import "tailwindcss"` + `@theme{}` never expand without the real pipeline, so the storybook build is the only source of real utility CSS). **Do not copy this file to a new location** — its `@font-face url()`s are relative to its original directory; copying it elsewhere silently drops every font file (validate won't always catch this — it only flagged 1/14 dangling rules when this bit us). On every sb-reference rebuild, the filename hash changes — update `cfg.cssEntry` to match.
- No built `dist`/`.d.ts` exists, so the converter's export-detection (`exportedNames`/`loadDts`, which only scans `.d.ts` trees) sees nothing by default. Fix: `.design-sync/package.json` (`{"name": "@echo/web", "types": "./.design-sync/entry.d.ts"}`) sits next to `entry.ts` so the ancestor-package-json walk resolves there instead of the repo root; `.design-sync/tsconfig.entry.json` (`tsc --declaration --emitDeclarationOnly`, extends `apps/web/tsconfig.json`) generates real `.d.ts` for the entry + every component it re-exports. Re-run `apps/web/node_modules/.bin/tsc -p .design-sync/tsconfig.entry.json` (NOT `npx tsc` — that resolved a different/stale TypeScript that couldn't parse `ts-pattern`'s .d.ts) whenever component prop shapes change; declaration output lands (due to rootDir/outDir math) at `.design-sync/.design-sync/entry.d.ts` and `.design-sync/apps/web/src/components/ui/*.d.ts` — don't be alarmed by the doubled nesting, that's expected and gitignored.
- `.design-sync/node_modules` is a symlink to `../apps/web/node_modules` — needed so the ts-morph dts scan (which walks up from `pkgDir` = `.design-sync`, an ancestor-only walk) can find `@types/react`. Without it every component with inherited DOM props emits an empty `.d.ts` body.
- `storyImports.shim: ["/components/ui/"]` is required because our filenames are kebab-case (`button.tsx`) while exports are PascalCase (`Button`) — the automatic per-file/per-dir export-name matcher (`exportedComponentFor`) never matches, so without this override every preview would bundle a second source copy of each component instead of rendering the real shipped bundle. The substring is broad enough to also catch `components/ui/event-calendar/*`, but those stories are excluded via titleMap so it never matters.
- `titleMap` excludes three non-presentational stories that live under `components/ui/` but aren't part of the design system: `"UI/EventCalendar": null`, `"UI/EventDetail": null`, `"EventCalendar/EventAttachments": null`.
- `overrides.Card: {cardMode: "column"}` — Card stories render wider than the grid cell (data-heavy cards).
- `overrides.Sidebar: {cardMode: "single", primaryStory: "Default"}` — Sidebar uses fixed/portal positioning (SidebarProvider + SidebarInset layout) that a normal grid cell can't contain; validate reported `root empty` until this was set.
- Storybook's `.storybook/preview.tsx` decorator (`withTRPC`, wraps stories in `trpc.Provider`/`QueryClientProvider`) fails to bundle: `Could not resolve "tailwindcss"` (the decorator file also does `import "../src/index.css"`, which esbuild can't process as JS). Previews render WITHOUT this provider chain. This is expected to be harmless — every component under `components/ui/` is presentational per AGENTS.md and none call trpc/react-query hooks directly. Re-verify this assumption if a future component under this path does start using query hooks (set `cfg.provider` then, or fork the decorator entry to drop the CSS import).
- `EventGallery`'s stories use `https://example.com/*` as fixture URLs — these never resolve **by design** (not a sandbox/network artifact), and both the storybook oracle and our preview render the identical broken-image fallback. Graded `match`. **[STALE as of 2026-08-11: `EventGallery` was removed from the repo — see below.]**
- **[GENERAL, 2026-08-11] Lingui macros break the main bundle, not just previews.** Since the first sync, `apps/web/src/components/ui/*.tsx` adopted `@lingui/react/macro` (`Trans`, `useLingui`) per AGENTS.md's i18n convention. `Trans`/`t` imported from `@lingui/react/macro` are guard functions that throw `"The macro you imported ... is being executed outside the context of compilation"` unless transformed away by Lingui's SWC/Babel plugin — a transform esbuild never runs. This broke **100% of components** (`[BUNDLE_EXPORT]` + `[RENDER] root empty` on all 25) — a global cause, not per-component. `story-imports.mjs`/`cfg.storyImports` only govern PREVIEW compiles, not the core `_ds_bundle.js` entry build (`lib/bundle.mjs`'s `sharedBuildOptions` hardcodes its plugin list and `bundle.mjs`/`emit.mjs` may never be forked), so the fix had to go through `cfg.tsconfig`'s existing `tsconfigPathsPlugin` seam instead: `.design-sync/tsconfig.build.json` (a small tsconfig that duplicates the real `@/*` path aliases from `apps/web/tsconfig.json` — the plugin reads only the ONE file `cfg.tsconfig` points at, never its `extends` chain — plus one extra alias, `"@lingui/react/macro": ["./overrides/lingui-macro-shim"]`) redirects the macro import to `.design-sync/overrides/lingui-macro-shim.tsx`, a stub that renders `Trans`'s children as-is and gives `useLingui()` a tagged-template `t` that just interpolates. This is a genuine visual match under the default "en" locale (Lingui falls back to source text when no translation is active), confirmed via the compare sheets. `cfg.tsconfig` now points at `./tsconfig.build.json` instead of the real `apps/web/tsconfig.json` — if `apps/web/tsconfig.json`'s `paths` ever change, mirror the change into `tsconfig.build.json` too (it's a manual copy, not an extends-merge). If a component starts using the `t`/`msg`/`plural` macros from `@lingui/core/macro` (not just `@lingui/react/macro`), extend the shim + path mapping the same way.
- `conventions.md` claimed a `destructive-foreground` CSS token existed; it doesn't — `Button`/`Badge`'s destructive variant uses `bg-destructive/10 text-destructive` (tinted, not solid+foreground). Fixed 2026-08-11; re-verify token names in conventions.md against `_ds_bundle.css` on future syncs since the table isn't machine-checked.

## Re-sync risks

- `cssEntry`'s filename is a content hash (`iframe-<hash>.css`) that changes every time `.design-sync/sb-reference` is rebuilt — must be updated in config.json after every reference rebuild, or the build silently falls back to whatever CSS esbuild picked up as a JS-import side effect (in our case, an unrelated `video-player/styles.css`, which produces a fully-unstyled-looking bundle with no loud error).
- The TRPC decorator failure (above) is accepted, not fixed — if it starts mattering (a component under `components/ui/` starts using tRPC/react-query), revisit with `cfg.provider`.
- `Input`, `Slider`, `Spinner`, `PhantomInput` `[RENDER_THIN]`/`[RENDER_BLANK]` warnings were triaged during fan-out grading: all confirmed as the component's legitimate minimal default state (both storybook and preview render the same bare content) — not defects, no fix applied.
- `overrides.Sidebar.skip: ["ui-sidebar--collapsed"]` — the `Collapsed` story is `sb-error` in the reference storybook itself ("`Tooltip` must be used within `TooltipProvider`" — the story wraps `SidebarMenuButton tooltip=...` without a `TooltipProvider` decorator). Not a preview defect; `Default` (primaryStory) is a clean match.
- Known framing artifact (storybook screenshots tightly auto-cropped vs our full-viewport captures) was re-confirmed across every fan-out batch — always sanity-check apparent size deltas against `_screenshots/compare/raw/` before treating them as real.
- DropdownMenu/Tooltip: none of their stories open the portal content (no `play` interaction), so both panels show only the closed trigger — no portal-bleed risk observed in this repo's stories for these two components.

## Re-sync risks (current as of 2026-08-11)

- `entry.ts` drifts silently from the real `components/ui/` directory (it's hand-maintained, not generated) — always diff it before building; see the Repo shape note above.
- `.design-sync/tsconfig.build.json`'s `paths` are a **manual duplicate** of `apps/web/tsconfig.json`'s `@/*` aliases (the tsconfig-paths plugin doesn't follow `extends`) — if the app's real path aliases change, this file goes stale silently (the build would just fail to resolve `@/...` imports with a normal `[UNRESOLVED_IMPORT]`, not a subtle bug, but worth knowing why).
- The Lingui macro shim (`.design-sync/overrides/lingui-macro-shim.tsx`) only covers `Trans` and `useLingui` — the only two macros currently used in `components/ui/*.tsx`. A future component using `t`/`msg`/`plural` from `@lingui/core/macro` directly will hit the same class of failure; extend the shim rather than rediscovering the root cause.
- `_ds_sync.json`'s `EventGallery` render hash is gone (component removed 2026-08-11, replaced by unstoried `Attachment`/`AttachmentList` — no story exists for either yet, so neither has a synced card; see the unstoried-components list above).
